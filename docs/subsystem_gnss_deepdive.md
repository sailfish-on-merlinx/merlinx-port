# Subsystem Deep Dive: GNSS & Positioning Architecture (MediaTek MT6768 / Merlinx)

## 1. Executive Summary

Global Navigation Satellite System (GNSS) on modern mobile chipsets combines multi-constellation satellite reception with Assisted GPS (A-GPS) over cellular/Wi-Fi to achieve fast Time-to-First-Fix (TTFF). On prior ports such as `karatep` (Qualcomm MSM8937), GPS was plagued by severe acquisition delays (minutes to fix, failing indoors) because assistance data injection was silently blocked by a ConnMan captive-portal state check.

On the **MediaTek Helio G85 (MT6768 / `merlinx`)**, reverse engineering of the live Android stack and vendor binaries reveals:
1. The GNSS engine runs under a dedicated userspace daemon: **`mnld` (MediaTek Navigation Location Daemon)**.
2. Inter-Process Communication (IPC) between the Android HAL and `mnld` uses simple **abstract UNIX datagram sockets (`@mtk_hal2mnl` and `@mtk_mnl2hal`)** with a clean binary framing protocol.
3. **`mnld` calculates and emits literal, standard NMEA 0183 sentences (`$GPGGA`, `$GPRMC`, `$GPGSV`, `$GPGSA`) directly over `@mtk_mnl2hal`**!
4. Assistance is handled by **`mtk_agpsd`**, implementing **OMA SUPL 2.0 over TLS to `supl.google.com:7275`** with 3GPP LTE Positioning Protocol (LPP/LPPe), supporting GPS, GLONASS, BeiDou, and Galileo.

This architecture enables two independent, highly viable integration strategies for Sailfish OS:
- **Strategy A (Standard Hybris)**: Drive `android.hardware.gnss@2.1` via `geoclue-providers-hybris`, applying the `karatep` ConnMan `ReadyState` patch.
- **Strategy B (Native NMEA Socket Bridge)**: A standalone, 100-line C daemon (`mtk-nmea-bridge`) that communicates directly with `mnld`, receives standard NMEA sentences, and feeds `/dev/ttyGPS` for native Linux `gpsd` / `geoclue-provider-nmea`, bypassing Android Binder and Java entirely.

## 4. Reverse Engineered Socket Protocol: `@mtk_hal2mnl` & `@mtk_mnl2hal`

Disassembly of `/vendor/lib64/hw/gps.default.so` and `mnld` reveals the binary framing protocol used over abstract UNIX datagram sockets:

### A. Message Framing Format
Every message exchanged over `@mtk_hal2mnl` and `@mtk_mnl2hal` uses little-endian 32-bit integers:

```text
+-----------------------+-----------------------+---------------------------------------+
| Field                 | Type / Length         | Description                           |
+-----------------------+-----------------------+---------------------------------------+
| Version / Magic       | uint32_t (4 bytes)    | Protocol version = 0x00000001         |
| Command Opcode (CMD)  | uint32_t (4 bytes)    | Command identifier (e.g. 0x65, 0x66)  |
| Payload               | Variable              | Command-specific arguments or data    |
+-----------------------+-----------------------+---------------------------------------+
```

### B. Command Opcodes (`hal2mnl`)
Disassembled from `gps.default.so`:

| Opcode | Hex | Symbolic Name | Function / Payload |
| :--- | :--- | :--- | :--- |
| `101` | `0x65` | `HAL2MNL_GPS_INIT` | Initializes the GNSS hardware engine and resets session state. |
| `102` | `0x66` | `HAL2MNL_GPS_START` | Starts satellite acquisition. Payload: `float fix_rate` (typically `1.0` Hz). |
| `103` | `0x67` | `HAL2MNL_GPS_STOP` | Stops positioning session, powers down RF frontend. |
| `104` | `0x68` | `HAL2MNL_GPS_CLEANUP` | Releases all allocated memory and closes device handles. |
| `105` | `0x69` | `HAL2MNL_GPS_INJECT_TIME` | Injects UTC timestamp (int64_t ms, int32_t ref, int32_t uncertainty). Verified in live logcat: `hal_gps_inject_time time=1792778679163`. |
| `106` | `0x6A` | `HAL2MNL_GPS_INJECT_LOCATION` | Injects coarse reference lat/long/accuracy. |
| `107` | `0x6B` | `HAL2MNL_GPS_DELETE_AIDING_DATA` | Clears ephemeris / almanac / NVRAM for cold start testing. |
| `108` | `0x6C` | `HAL2MNL_GPS_SET_POSITION_MODE` | Configures Standalone, MS-Based (MSB), or MS-Assisted (MSA). |
| `109` | `0x6D` | `HAL2MNL_SET_SERVER` | Sets SUPL server FQDN/IP and port (e.g. `supl.google.com:7275`). |

### C. Response Callbacks (`mnl2hal`)
Disassembled from `mnl2hal_hdlr` in `gps.default.so`:

| Callback Name | Handler Mechanism | Description |
| :--- | :--- | :--- |
| **`mnl2hal_nmea`** | `get_binary(buf, &offset, length)` | **Literal ASCII NMEA 0183 sentences (`$GPGGA`, `$GPRMC`, `$GPGSV`, `$GPGSA`).** Ready for immediate consumption by standard GPS parsers. |
| **`mnl2hal_location`** | Struct unpack | Binary PVT solution (Latitude, Longitude, Altitude, Speed, Bearing, Accuracy, Timestamp). |
| **`mnl2hal_gps_sv`** | Struct unpack | Space Vehicle (SV) status array (PRN, C/N₀ SNR, Elevation, Azimuth, Constellation type, Ephemeris flags). |
| **`mnl2hal_gps_status`** | uint32_t | GNSS engine status (NONE, SESSION_BEGIN, SESSION_END, ENGINE_ON, ENGINE_OFF). |
| **`mnl2hal_request_utc_time`** | Event trigger | Requests NTP time injection when internal clock drift exceeds threshold. |
| **`mnl2hal_request_data_conn`**| Event trigger | Requests cellular data context activation for SUPL exchange. |

## 6. RCA Alignment: Solving Karatep's ConnMan Assistance Bug

In the `karatep-port` investigation (`docs/rca/gps-cold-start-no-assistance.md`), the root cause of slow fixes was identified in `geoclue-providers-hybris`:

```cpp
// Karatep failure: gated on OnlineState which required Jolla captive portal return_204
if (m_networkManager->globalState() == NetworkManager::OnlineState) {
    if (m_useForcedXtraInject) gnssXtraDownloadRequest();
    if (m_useForcedNtpInject)  injectUtcTime();
}
```

Whenever the device was offline, behind a firewall, or connected to Wi-Fi without Internet access, ConnMan remained in `ReadyState`. Time injection and assistance downloads were completely skipped, leaving the modem to demodulate 50 bps satellite broadcast frames in the blind.

### Merlinx Solution:
1. **Apply the Verified Karatep Patch**: Change `== NetworkManager::OnlineState` to `>= NetworkManager::ReadyState` in `geoclue-providers-hybris` for `merlinx`.
2. **Autonomous SUPL**: Because `mtk_agpsd` handles its own TLS socket connection directly to `supl.google.com:7275`, it does *not* depend on `geoclue` HTTP injection if internet connectivity is present. As long as `mtk_agpsd` is running and DNS resolves, SUPL assistance succeeds autonomously.

## 7. Dual Implementation Architecture for Sailfish OS

### Option A: Standard Mer-Hybris HIDL Stack
- **Architecture**: Sailfish OS `geoclue` -> `geoclue-providers-hybris` -> `android.hardware.gnss@2.1-impl-mediatek.so` -> `@mtk_hal2mnl` -> `mnld`.
- **Pros**: Standard Sailfish OS packaging, integrated with system privacy toggles and location settings.
- **Requirements**:
  - Keep `android.hardware.gnss-service.mediatek`, `mnld`, and `mtk_agpsd` running in `droid-hal`.
  - Apply the `ReadyState` patch to `geoclue-providers-hybris`.

### Option B: Native `mtk-nmea-bridge` Daemon (Recommended Architectural Alternative)
Because `mnld` outputs complete, pristine NMEA 0183 sentences over `@mtk_mnl2hal`, we can deploy a tiny, native C daemon (`mtk-nmea-bridge`):

```c
/* Pseudocode of mtk-nmea-bridge */
int fd_hal2mnl = socket(AF_UNIX, SOCK_DGRAM, 0);
int fd_mnl2hal = socket(AF_UNIX, SOCK_DGRAM, 0);
bind_abstract(fd_mnl2hal, "mtk_mnl2hal");

/* 1. Send HAL2MNL_GPS_INIT (cmd=101) */
uint32_t init_pkt[] = { 1, 101 };
sendto_abstract(fd_hal2mnl, "mtk_hal2mnl", init_pkt, sizeof(init_pkt));

/* 2. Send HAL2MNL_GPS_START (cmd=102, rate=1.0f) */
struct { uint32_t ver; uint32_t cmd; float rate; } start_pkt = { 1, 102, 1.0f };
sendto_abstract(fd_hal2mnl, "mtk_hal2mnl", &start_pkt, sizeof(start_pkt));

/* 3. Read NMEA loop */
while (1) {
    uint8_t buf[4096];
    int len = recv(fd_mnl2hal, buf, sizeof(buf), 0);
    if (is_nmea_packet(buf, len)) {
        write(pty_master_fd, extract_nmea(buf), nmea_len);
    }
}
```

- **Pros**:
  - Bypasses Android Binder, `hwservicemanager`, and `libbinder.so` entirely for location services.
  - Exposes a standard virtual serial port `/dev/ttyGPS` compatible with native Linux `gpsd` and standard `geoclue-provider-nmea`.
  - Immune to Android HAL version changes or HIDL deprecation in future Android bases.
